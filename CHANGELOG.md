# Changelog

- Чистый checkout запускает полный набор тестов и явно пропускает только проверки, требующие отсутствующих локальных материалов или инструментов; GitHub CI запускает полный pytest с Chromium без закрытых данных.
- В кабинете отдельно показаны пропуск ИИ-проверки из-за неактуального каталога и отсутствие подходящей позиции при подтверждённом назначении. Логика подбора не менялась.

- Закрытый кабинет отклоняет экспериментальные маршруты на уровне бэкенда. Чтение указателя каталога не следует символическим ссылкам и ограничивает размер. Добавлены зависимости с хешами, политика данных и проверяемый экспорт исходников для публикации.

- Проверенные результаты публичного ИИ-исследования повторно используются в течение часа без вызова DeepSeek; клиентская история и резервная подборка не кэшируются. В запросе САПР теперь до 10 релевантных отрывков вместо 28, лимит структурированного ответа снижен до 128 токенов.

- Для закрытого стенда подключён `deepseek-flash` с ключом через systemd credentials. Лимит кабинета теперь временный: 8 запусков за 10 минут, HTTP 429 провайдера даёт паузу на минуту вместо блокировки до перезапуска.

- Упростили объяснение последовательных покупок и добавили отдельный демо-профиль для проверки покупки модуля nanoCAD. Документированный отказ виден в подборке и в графе; общие товары не отображаются как ответ на отклонённый запрос.

- Единая кнопка подбора запускает сценарий без внешней передачи истории. Для защиты рабочих мест модель исследует фиксированный публичный случай, а результат локально сверяется с историей; для новых клиентов с задачей САПР модель выбирает источник и цитату, проверенный результат может занять первое место либо отдельная покупка отклоняется по FAQ. В графе выделены данные продаж, подтверждённое назначение, условная применимость и отказ; обе исторические строки подписаны Baseline.

- Закрытый «Личный кабинет клиента»: курированные разные истории с однозначными кандидатами сопоставления, сценарий нового клиента, короткие причины прямо в карточках и один граф оснований. Документация подставляется автоматически; платформа — опциональный строгий фильтр по каталогу без модели. Технические проверки остались вне кабинета. Precision@3 и оба базовых метода показаны в одном блоке; исторический расчёт и стандартная тройка не менялись.

- Утверждённый дизайн перенесён в закрытый стенд. Клиентская причина и «Обоснование выбора» разделены; условные дополнения и обновления с документом производителя видны отдельно и не меняют топ‑3. Описание заявки синхронизировано.
- Добавлен аудит покрытия SKU v5 по первой причине отказа: отсутствие соответствия отделено от неоднозначности, продления, аудитории и наличия. Правила ранжирования не менялись.

- Подготовлено отдельное закрытое превью интерфейса: видимые клиентские причины, явные изменения топ‑3 при проверке архитектуры и самостоятельный экран исторической оценки. Основной стенд не заменён; обновлён сценарий видео.

- На закрытом стенде показан контроль холодного старта на том же пуле v5: 316 против 322 попаданий. Агентный сценарий показывает выбор источника, загрузку и подтверждение цитаты отдельно от метрики.

## 27.11 — разные причины рекомендаций
- В карусели отдельно показаны совместная корзина, следующая наблюдаемая покупка, популярность и сходство каталога. Для переходов считаются разные клиенты, а не число повторных покупок одного клиента; счётчик не влияет на порядок.
- Автоматический исследователь формулирует условную задачу клиента и отличает найденный дополнительный товар от уже показанного в карусели. Статистическая тройка не меняется; предметная пригодность по-прежнему требует проверки.
