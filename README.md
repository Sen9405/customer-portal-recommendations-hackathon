# Рекомендации в личном кабинете — демонстрационный каркас

В публичном репозитории нет датасета организатора, baseline-файла организатора или ключей. `demo_server.py` работает на синтетических историях без установки пакетов. Для закрытого Linux-стенда зависимости зафиксированы: `python3 -m pip install --require-hashes -r requirements.txt`, для разработки — `requirements-dev.txt` и `python3 -m playwright install chromium`. Некоторые тесты исторических результатов требуют локальных файлов организатора. Перед отправкой исходников см. [правила безопасности и проверку состава](SECURITY.md).

Демо-интерфейс получает подбор от локального экспериментального алгоритма. Товары, профили, покупки, связи и проверка наличия в подборке синтетические; данные заказчика и модель ИИ не подключены. Отдельный справочный блок Kaspersky основан на открытых источниках и не подключён к подбору. Это не конкурсные метрики и не доказательство качества рекомендаций.

## Запуск интерфейса локально

```bash
python3 -B demo_server.py 18765
```

Открыть http://127.0.0.1:18765/. Запуск с 127.0.0.1 доступен только на этой машине.

## Закрытый просмотр реальных данных

`CABINET_ONLY=1 python3 -B closed_review_server.py 18766` запускает **закрытый кабинет** на предоставленных отдельно данных v5. Открывать только на этой машине по адресу http://127.0.0.1:18766/ и завершать Ctrl-C. Истории, товары и кандидаты содержат закрытые данные: не записывать для публичного видео, не публиковать и не пересылать. Опциональный Hermes отправляет названия и сведения истории внешнему провайдеру, требуя согласия. Предметные категории — лишь гипотезы по названиям, не проверка потребности или совместимости. Прототип не является клиентской выдачей: совпадения SKU и полнота истории не подтверждены, наличие показано только по текущему снимку, не в реальном времени. Локальный порт не защищает от других процессов и пользователей этой машины; это не production-сервер.

## Проверки

Автоматический исследователь в закрытом демо: `RESEARCH_PREFETCH_PUBLIC=1 python3 -B closed_review_server.py 18770`. При запуске загружается фиксированный набор публичных страниц независимо от истории клиента. При открытии профиля локально проверяется наблюдаемая покупка и, если есть основание, показывается гипотеза с документом производителя и кандидатом из текущего фида. Один подходящий профиль поставлен первым для демонстрации. Гипотеза не входит в топ-3 и не доказывает потребность, права на лицензию или идентичность покупки. Открытие профиля не вызывает внешний поиск или LLM. Поддерживаются два узких сценария; фактическое покрытие v5 — Kaspersky (28 профилей); для серверного КриптоПро CSP 4.0 нет однозначно сопоставленной истории.

```bash
python3 -m unittest discover -s tests -v
python3 -m evaluation
node --check web/app.js
```

Модуль оценки считает Precision@3 с фиксированным знаменателем и исключает клиентов без известного будущего из усреднения precision; fill rate — доля всех клиентов в переданной когорте хотя бы с одной рекомендацией. Дополнительно показывается заполнение трёх слотов. Временное разделение глобальное, события на границе с одинаковой отметкой целиком попадают в test. Схема и политика оценки предварительные и требуют согласования с заказчиком.

Модуль `evaluation` без дополнительных параметров использует синтетические данные. `evaluation.protocol_audit` воспроизводит списки и метрики официальных popularity и co-purchase на v4; корзина — `(order_id, order_week)`. Ранее расхождение было вызвано другой группировкой корзин и исправлено. Авторизация клиентского кабинета и DeepSeek не подключены; локальный синтетический API демо работает.

## Локальный аудит данных и каталога

```bash
python3 -B -m evaluation.protocol_audit data/dataset.xlsx
python3 -B -m catalog.softline_audit data/dataset.xlsx data/softline-audit.json
python3 -B -m recommendation.experimental_graph data/dataset.xlsx
python3 -B -m catalog.softline_features data/dataset.xlsx data/softline-features.json
python3 -B -m recommendation.catalog_similarity data/dataset.xlsx data/softline-features.json
```

Для чтения XLSX требуется `openpyxl`. Второй скрипт потоково читает текущий публичный фид; выходной файл создаётся только один раз внутри `data/` и содержит конфиденциальные производные данные. Не публикуйте его или исходный XLSX. Совпадение SKU — кандидат, не доказательство идентичности. Текущий фид не является историческим снимком на дату бэктеста.

Третий скрипт — старый исследовательский эксперимент v3: граф группирует по `order_id`, поэтому не реализует подтверждённое позднее правило `(order_id, order_week)` и не является официальным baseline. Выбор нескольких вариантов по одному тесту не доказывает улучшение.

Четвёртый скрипт сохраняет в закрытой `data/` признаки текущего фида для однозначных кандидатов сопоставления. Пятый — исследовательская проверка похожести товаров по категории и производителю на этом подмножестве. Его данные содержат сведения из будущего и выборку товаров из всей истории; это не честный исторический бэктест. Сходство не является совместимостью. В `sources/manufacturer_relations.json` отдельно зафиксированы три связи из документации производителей; сопоставление этих связей с SKU ещё не сделано.

## Экспериментальный гибрид

`catalog.catalog_index` создаёт потоковый SQLite-индекс всего фида в `data/`. `recommendation.hybrid.Hybrid` объединяет граф покупок, проверенные связи из реестра, похожесть по каталогу и резервную популярность. `python3 -B -m recommendation.hybrid` запускает только синтетический пример. На реальных данных метод должен вызываться локально: результаты содержат закрытые идентификаторы. Без подтверждённой полной истории, идентичности товаров и реальной проверки наличия гибрид не выдаёт рекомендации; реальные подтверждения и проверка наличия пока не подключены. Реальных проверенных связей реестра с SKU пока нет. Совпадение категории не утверждает совместимость; корректность и полнота подтверждений зависит от внешней проверки.

`python3 -B -m recommendation.segmented_history data/dataset.xlsx` выполняет отдельные ретроспективные эксперименты с сегментом и отраслью. Эти поля и группа клиента не имеют даты актуальности: результаты потенциально содержат информацию из будущего. В гибрид они пока не включены.

`python3 -B -m recommendation.temporal_selection data/dataset.xlsx` выбирает модель по раннему периоду и оценивает на официальном: продажи только до среза, открытый фид в обучении не используется. Официальный тест уже наблюдался при прежних экспериментах, поэтому независимым отложенным тестом его считать нельзя. Доступность товаров на дату среза неизвестна.

`python3 -B -m recommendation.sequential_diagnostics data/dataset.xlsx` исследует устойчивость последовательных рекомендаций: значительная часть выигрыша чувствительна к исключению связей между лексически похожими названиями. Это грубая эвристика, а не подтверждение тождества товаров.

`python3 -B -m recommendation.variant_sensitivity data/dataset.xlsx` отдельно показывает чувствительность метрик к лексически похожим названиям. `recommendation.availability_adapter` требует отдельно предоставленных проверяемых поставщика и проверки доказательств; реальный поставщик наличия не подключён.

`python3 -B -m catalog.review_priority data/dataset.xlsx data/identity-review.sqlite` показывает только агрегаты очереди проверки соответствий. Очередь и решения хранятся локально, автоматического подтверждения нет. Для тестов браузера требуется Playwright и Chromium; `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q` отключает несовместимые глобальные плагины pytest.

`python3 -B -m recommendation.restricted_dry_run` — закрытый агрегатный прогон реальных историй без проверки наличия и без аттестации полноты истории; при текущих данных он корректно блокирует все реальные рекомендации. Публичные кандидатные связи в `sources/public_catalog_pair_evidence_20261126.json` не утверждены для конкретных лицензий или клиентов и не подключены к выдаче. Черновик вопросов организаторам находится в `docs/QUESTIONS_ORGANIZERS.md`; пользователь сообщил, что отправил сокращённую версию.

`python3 -B -m recommendation.hybrid_evaluation data/dataset.xlsx data/softline-features.json` сравнивает исследовательские кандидаты и абляции; канал текущего каталога заведомо содержит информацию после исторического среза и не является корректным историческим тестом. Это не production-гибрид и не проверка доступности. Приватный `data/identity-review-worksheet-top25.html` предназначен только для локальной ручной проверки и не является подтверждением. В `docs/VIDEO_SCRIPT.md` и `docs/SUBMISSION_DRAFT.md` лежат черновики; конкурсный ролик, публичный стенд и расчёт стоимости ещё не готовы.

`recommendation.public_evidence_agent` предоставляет ссылки из ограниченного реестра; это не произвольный поиск и не проверка конкретного SKU. В закрытом интерфейсе opt-in исследователь `recommendation.catalog_researcher` использует два вызова внешней модели Hermes для выбора направлений и оценки найденных предложений. Тестовый CLI не является сетевой песочницей, провайдер может хранить сессии. Отбор по названию не доказывает полезность; в малой предварительной самопроверке модели 5 из 6 показанных гипотез получили оценку «только общая связь», источников у них не было. Это не независимая экспертиза и не измерение качества. Автоотправка клиенту заблокирована. Приватный `data/private-live-demo-plan-20261126.md` описывает закрытый показ, а не разрешение на запись или публикацию.
