# v5: отдельная оценка холодного старта

Запуск: `python3 -B -m recommendation.v5_cold_start_eval`. Официальные A/B не меняются. Здесь холодные — клиенты без покупок до отсечки 31.08.2026, но с покупкой после неё. Цель — товары первой наблюдаемой недели, а не все последующие покупки. Это первая покупка в выгрузке, не доказательство, что клиент впервые покупал у Softline. Тип и отрасль взяты из недатированных полей v5, то есть предполагаем, что эти признаки известны на старте. Цель и архитектуру для ретротеста не подглядываем из покупок: не задаём их. LLM не участвует.

Совместные покупки без истории возвращают пустой список. У всех непустых методов полные тройки в режиме без цели и архитектуры. Три строки стенда используют одинаковый пул на тип клиента (товары, купленные клиентами этого типа на train, однозначный mapping, те же фильтры снимка). У контрольного метода веса глобальные, у нашего — по типу и отрасли. Итог: 6,79% → 6,92%, +6 попаданий, все в B2B; отрасль дала +1 к ранжированию по типу. Это ретротест с ноябрьским снимком, не проверка исторического наличия или официальная метрика. LLM в замере не участвует, её выбор источника и проверка задачи показаны отдельно на стенде.

## Покрытие реального резерва

Перебраны все 320 комбинаций формы: тип клиента и допустимая отрасль B2B, категория (включая САПР для агента), архитектура. Это конфигурации, а не распределение посетителей. В 93 было три товара, в одной — один, в 226 — ни одного. Без выбранной архитектуры 79 из 80 непустые (78 полных); пустой сценарий — B2C с целью резервного копирования. При строгом ARMv8 или Эльбрусе пуст весь статистический резерв: у кандидатов нет подтверждённого совпадения архитектуры после всех текущих фильтров. Это не означает, что таких продуктов нет во всём фиде. Chromium подтвердил пустой ARMv8 B2B, пустой резерв B2C по бэкапу и полную общую подборку B2C.

После расширения резерва на том же снимке: 320/320 непустых, из них 316 троек и четыре выдачи по одному товару. Сначала сохраняются категория и архитектура, при отсутствии результата расширяется поиск; 15 сочетаний показывают только варианты для обзора, без подтверждения соответствия архитектуре. Тип клиента и `available=true` сохраняются на всех ступенях. Новый результат — покрытие формы, не новый Precision@3.
